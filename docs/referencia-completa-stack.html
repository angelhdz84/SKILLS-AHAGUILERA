B. Inventario de Skills 69 total

B1. Skills del Stack 16

Skills del pipeline principal y modulos operativos del stack offline-first. Instaladas en ~/.opencode/skills/.

prompt-inicial orquestador nuevo proyecto

Orquesta el pipeline completo: recibe 5 campos del usuario (nombre, tipo, descripcion, tono, modulos) y dispara setup → spec → generacion → validacion.

setup-init infraestructura iniciar setup

Valida entorno, crea estructura de carpetas, genera project.config.js y script de descarga de librerias locales (DaisyUI 5 + Tailwind 4 runtime).

spec-creator especificacion definir spec app

Transforma historias de usuario en specs tecnicas validadas. Flujo interactivo: asunciones con barra de progreso, preguntas 4+1, auto-revision, deteccion de librerias externas via context7 MCP.

design-ux-intelligence diseno auto + tono visual

Aplica principios de diseno profesional con paletas de marcas reales (refero-styles MCP), tipografia, componentes Pines y validacion WCAG AA. Se auto-activa al mencionar tono visual.

code-generator generacion generar codigo

Genera codigo por fases: core primero, luego modulos uno a uno. Fase A = index.html + core/; Fase B = modulos/. Pausas explicitas entre modulos. Lee spec y aplica estilo de design-ux.

stack-compliance-guard validacion auto post-generacion

Guarda automatica: bloquea imports ES6, CDNs, fetch y omision de cifrado. Corrige automaticamente lo reparable. Se ejecuta tras cada output de codigo. Tambien manual con validar stack.

validation-offline testing validar app

Validacion final: analisis estatico + guia DevTools (consola, Lighthouse, network) + tests Playwright + auditoria a11y + checklist de entrega. Genera reporte en docs/validacion-[app].md.

ux-refactor refactor mejorar UI

Audita y mejora UX/UI de apps existentes sin regenerarlas. 4 fases: auditoria → recomendacion (refero-styles + pattern-matrix) → implementacion in-place → validacion (compliance + a11y).

daisyui-patterns componentes daisyui

Patrones DaisyUI 5 optimizados para Alpine.js + offline-first. Referencia oficial via daisyui-gitmcp MCP. Consumido por code-generator, design-ux, ux-refactor.

llm-wiki conocimiento guarda esto

Wiki persistente con paginas markdown (wiki/) + grafo en MCP memory. 3 modos: ingest (procesar fuentes), query (responder desde wiki), lint (revisar salud). Auto-activado tras spec, code-gen, validation.

ia-jutia mini IA mini ia

Mini IA offline-first. Lite: FlexSearch + estadisticas + predicciones. Full: + ingesta PDF/DOCX/XLSX/CSV/MD + Transformers.js QA extractivo. Atajo global Cmd+K.

deployment-jigue deploy publicar

Publica cambios a GitHub, despliega Pages y empaqueta segun perfil. Lite: ZIP + Pages. Full: bun build --compile .exe + Pages + Release.

supercharged-pipeline potenciado /pro

Pipeline potenciado por Superpowers: 7 fases con brainstorming → spec → writing-plans → subagents → dual review → deploy. Checkpoints humanos en cada fase.

mermaid-graph-writer diagramas mermaid

Escribe diagramas Mermaid precisos: flowcharts, sequence, state, ER, timeline, mindmap, Gantt. No renderiza, solo escribe sintaxis.

mermaid-graph-renderer diagramas render mermaid

Renderiza diagramas Mermaid a SVG/PNG/PDF. Cubre lazy loading, SSR, CLI batch export y rendering nativo Rust.

ux-ui-universal multi-stack refactorizar UI de

Audita y mejora UX/UI de cualquier app web (React, Vue, Angular, Svelte, Django, Rails, etc.). Detecta framework, adapta recomendaciones con context7, aplica cambios in-place. 4 fases.

B4. Superpowers Skills 14

Instaladas via plugin en ~/.config/opencode/node_modules/superpowers/skills/. Proporcionan procesos de ingenieria de software disciplinados.

brainstorming proceso

Explora intencion del usuario, requisitos y diseno antes de implementar. Obligatorio antes de cualquier trabajo creativo.

using-superpowers core

Skill de entrada: establece como encontrar y usar skills. Requiere invocar Skill tool antes de responder.

writing-plans proceso

Genera planes de implementacion multi-paso a partir de specs o requisitos. Descompone trabajo en tareas ejecutables.

executing-plans proceso

Ejecuta planes de implementacion escritos con writing-plans. Sesiones separadas con checkpoints de revision.

subagent-driven-development proceso

Desarrollo con subagentes independientes. Para tareas paralelas sin dependencias secuenciales. Usa implementer + reviewer.

dispatching-parallel-agents proceso

Despacha 2+ tareas independientes a subagentes en paralelo. Para trabajos sin estado compartido ni dependencias secuenciales.

test-driven-development proceso

TDD riguroso: red → green → refactor. Escribir test antes que implementacion. Anti-patrones incluidos.

systematic-debugging proceso

Debugging sistematico: 1) reproducir, 2) hipotesis, 3) experimento, 4) causa raiz, 5) fix + test. Guias de root-cause tracing, defense-in-depth.

writing-skills meta

Crea, edita y verifica skills. Testing con subagentes, principios de persuasion, mejores practicas Anthropic.

verification-before-completion proceso

Verifica que el trabajo esta completo antes de afirmar "listo". Ejecuta comandos de verificacion y confirma output antes de claims.

finishing-a-development-branch proceso

Completa el trabajo de desarrollo: opciones estructuradas para merge, PR o cleanup cuando todo pasa.

requesting-code-review proceso

Solicita revision de codigo al completar tareas o antes de mergear. Verifica que el trabajo cumple requisitos.

receiving-code-review proceso

Maneja feedback de code review: rigor tecnico, verificacion, no implementacion ciega. Para cuando el feedback no es claro.

using-git-worktrees proceso

Crea workspaces aislados via git worktree para trabajar en features sin afectar el workspace principal.

C. Pipeline

Clasico (/new) — 5 fases

prompt-inicial→ setup-init→ spec-creator→ design-ux-intelligence→ code-generator + compliance→ validation-offline→ deployment-jigue

PAUSA tras cada fase. No generar todo de una vez (OpenCode pierde contexto >15k tokens).

Supercharged (/pro) — 7 fases

brainstorming→ spec→ writing-plans→ subagents→ dual review→ deploy

Requiere Superpowers instalado. Fallback automatico a clasico si no esta disponible.

H. Reglas No Negociables

❌ Prohibiciones

  • import / export / type="module" (CORS en file://)
  • fetch / axios para datos (usar Dexie)
  • CDNs en runtime (todo local en assets/)
  • Build steps (la app se abre con doble clic)
  • Datos sin cifrar en campos sensibles

✔ Obligaciones

  • Variables globales: Alpine, Dexie, CryptoJS
  • cryptoHelpers.encrypt() en campos sensibles
  • UI: DaisyUI + Bootstrap Icons + Animate.css
  • Todo en espanol (UI, comentarios, docs)
  • Stack compliance post-generacion automatico
