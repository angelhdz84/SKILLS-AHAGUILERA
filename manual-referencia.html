🎯 El Stack Offline-First

Reglas no negociables que todo código generado debe cumplir. Definen el contrato del ecosistema.

Stack compliance

ReglaImplementación
No import/export/type="module"CORS en file:// bloquea ES6 modules. Usar variables globales (window.Alpine, window.Dexie).
No fetch/axios/CDNs100% offline. Datos en IndexedDB via Dexie. Librerías en assets/.
No build stepsDoble clic en index.html y funciona.
Campos sensibles cifradoscryptoHelpers.encrypt() con CryptoJS AES.
UI DaisyUI + Bootstrap IconsComponentes accesibles + iconografía vectorial consistente.
Todo en españolUI, comentarios, nombres de variables, documentación.
Librerías desde assets/Descarga local via setup-init. Nunca CDN.

Privacidad por Diseño

  • Datos mínimos: solo lo declarado en la spec
  • Consentimiento explícito antes de guardar
  • Datos opcionales marcados claramente
  • Cifrado AES en reposo

prompt-inicial v1.0 orquestador

Prompt maestro que inicia el pipeline. Recibe nombre, tipo y descripción de la app, y orquesta automáticamente setup → spec → generación → validación.

Trigger

"nuevo proyecto" · "iniciar setup"

Flujo

  1. Recibe nombre, tipo y descripción de la app del usuario
  2. Llama a setup-init para preparar el entorno
  3. Llama a spec-creator para generar especificación
  4. Orquesta code-generator + compliance-guard + validation-offline

Entrada

Nombre: "ClinikApp"
Tipo: "Gestion de pacientes"
Descripcion: "App offline para recepcionista de clinica medica"

setup-init v2.0 infraestructura

Prepara el proyecto offline-first: valida entorno, crea estructura exacta, descarga librerías base y adicionales desde repos GitHub locales.

Fases

  1. Validar entorno: curl, permisos de escritura, Node.js opcional
  2. Crear estructura: core/, modules/, assets/, specs/, tests/, docs/, _template/
  3. Descargar librerías base: Alpine.js, Dexie, CryptoJS, Tailwind, DaisyUI, Bootstrap Icons, Animate.css, pako, ApexCharts, jsPDF, SheetJS
  4. Detectar librerías adicionales desde spec y descargarlas a assets/

Contrato de Módulo

Cada módulo sigue: id, titulo, icono, init(), render(), destroy(). Los campos sensibles se cifran con cryptoHelpers.encrypt() automáticamente.

Output Enforcement

Reglas anti-truncación (de taste-skill/output-skill). El generador nunca debe producir placeholders, // TODO, // rest of code, ni descripciones sin implementación. Si se acerca al límite de tokens: [PAUSED — X of Y. Send "continue"].

stack-compliance-guard v2.3 guarda

Se auto-activa tras cada output de código. Bloquea imports, CDNs, fetch, y omisión de cifrado. Verifica librerías locales y aplica 34 anti-patrones determinísticos.

ReglaQué detecta
R1: Imports ES6import/export/type="module" → reemplazar por globales
R2: CDN/Fetchfetch()/axios/URLs absolutas → Dexie/assets
R3: CifradoCampos sensibles sin cryptoHelpers.encrypt()
R4: UISin DaisyUI/Bootstrap Icons/Animate.css
R5: MódulosSin contrato id/init/render/destroy
R6: LibreríasCDN o no listadas en spec
R7: Anti-patrones27 reglas impeccable + 7 supplement taste-skill
