📖 Manual de Uso de SKILLs

Aprende a usar las 7 SKILLs del stack offline-first con ejemplos prácticos. Cada skill tiene su propio comando slash y su trigger — usa el que prefieras.

💡 Cómo usar este manual: Busca la skill con la que quieras trabajar, lee el escenario de ejemplo y sigue los pasos en tu terminal de OpenCode.

🚀 /new — Iniciar un proyecto

El orquestador maestro. Recibe 5 campos, dispara el pipeline completo.

Uso básico

Escribe en OpenCode:

Tú: /new
OpenCode: Voy a iniciar el pipeline para tu nueva app.
  Por favor completa estos 5 campos:

📦 Nombre del proyecto: ClinicaDentalPro
🎯 Tipo de app: Gestión de citas y pacientes
💡 Descripción breve: App para recepcionistas que registra pacientes, agenda citas y exporta reportes diarios. Todo offline.
🎨 Tono visual (1-6): 1 (Profesional)
🔑 Módulos requeridos: dashboard, pacientes, citas, reportes, settings

→ Pipeline iniciado. Siguiente paso: /setup
🎯 Qué lograste
El orquestador guardó tu configuración y disparó prompt-inicial. Ahora puedes continuar con /setup o esperar a que OpenCode lo ejecute automáticamente.

🔌 MCPs en la práctica

Los MCPs trabajan en segundo plano. No necesitas invocarlos manualmente — las SKILLs los usan automáticamente. Así es como se integran:

MCPSKILL que lo usaCuándo se activa
context7 setup-init, spec-creator Al detectar librerías adicionales en la spec. Consulta la URL y versión actualizada.
excalidraw spec-creator Al finalizar la spec. Genera un diagrama hand-drawn de la arquitectura de módulos.
chrome-devtools validation-offline Durante /test. Captura consola, screenshots y ejecuta Lighthouse.
refero-styles design-ux Al buscar un tono visual. Obtiene design.md de marcas reales (Linear, Stripe, etc.).
a11y validation-offline, design-ux En /test fase 4 y al seleccionar paleta de colores (verifica contraste WCAG).
filesystem Todas Siempre. Cada lectura/escritura de archivos usa este MCP.
web-search setup-init (fallback) Solo si context7 falla. Busca la URL de la librería manualmente.
⚠️ Importante: Los MCPs canva y supabase no son usados por las SKILLs del stack. Están disponibles para uso manual si los necesitas.

🎬 Workflows completos

Workflow 1: App completa desde cero (15-30 min)

  1. /new — Escribe el comando y llena los 5 campos. El orquestador toma el control.
  2. /setup — Crea estructura, descarga librerías. Ejecuta el .bat cuando lo pida.
  3. /spec — Define la spec. Responde asunciones y preguntas 4+1. Revisa la spec generada.
  4. (opcional) Tono visual — Escribe "tono visual moderno" para que design-ux active el estilo.
  5. /build — Genera core + módulos. Confirma cada pausa con ✅ CORE OK y ✅ [módulo] OK.
  6. /test — Valida la app. Responde si tienes Python/Playwright. Recibe el reporte.
  7. Entrega — Abre index.html con doble clic. La app funciona 100% offline.

Workflow 2: Auditar proyecto existente (5 min)

Tienes un proyecto HTML/JS que quieres verificar si cumple el stack offline-first.

  1. Abre OpenCode en la carpeta del proyecto existente.
  2. Ejecuta /compliance. La skill escanea todos los archivos.
  3. Revisa las violaciones reportadas. Las corrige automáticamente o te pregunta.
  4. Ejecuta /test para la validación completa con reporte.

Workflow 3: Iterar sobre una app existente (10 min)

Ya tienes una app generada y quieres añadir una funcionalidad.

  1. Ejecuta /spec y selecciona "modificar app existente".
  2. Describe el nuevo módulo o funcionalidad que quieres añadir.
  3. Responde asunciones y preguntas. La spec se añade a la existente.
  4. Ejecuta /build. Solo genera los módulos nuevos, no sobreescribe los existentes.
  5. Ejecuta /test para validar todo el conjunto.
  6. Usa /archive para archivar la spec de la iteración anterior.

❓ Preguntas frecuentes

¿Cómo empiezo si no recuerdo los comandos?

Escribe /new. Es el único comando que necesitas recordar — el orquestador te guía paso a paso por todo el pipeline.

¿Qué hago si OpenCode pierde el contexto?

Escribe /context clear y luego repite el último comando. El pipeline está diseñado con pausas precisamente para evitar esto. Si perdiste el progreso, usa /status para ver en qué fase estás.

¿Puedo usar las SKILLs sin conexión a Internet?

Sí, una vez que las librerías están descargadas en assets/, todo funciona 100% offline. Los MCPs que requieren Internet (context7, excalidraw, refero-styles) solo se usan durante el desarrollo, no en la app final.

¿Cómo se entrega la app al cliente?

Copia toda la carpeta del proyecto (sin node_modules/, .git/) y envíala. El cliente abre index.html con doble clic y la app funciona. Puedes usar las plantillas en PLANTILLA DE CONTRATO FREELANCE.txt y PLANTILLA DE CORREO DE ENTREGA PROFESIONAL.txt.

¿Puedo usar mis propias librerías?

Sí. Durante /spec, el spec-creator detecta librerías adicionales según la descripción de tu app. También puedes añadirlas manualmente en la sección libreriasAdicionales de la spec. El sistema las descargará a assets/ y las cargará en index.html.

¿Por qué mi app no abre con doble clic?

Posibles causas: (1) hay un import o type="module" en el HTML — ejecuta /compliance para detectarlo y corregirlo. (2) Las rutas de los scripts en index.html no son relativas — verifica que usen src="assets/js/..." y no src="https://...".
